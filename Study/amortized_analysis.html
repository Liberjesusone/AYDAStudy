Análisis Amortizado

Distribuir el costo de operaciones caras sobre las baratas para obtener una cota más realista.

¿Por qué existe?

El problema: algunas estructuras tienen operaciones que cuestan O(n) en el peor caso, pero ese caso ocurre raramente. El análisis por caso peor operación a operación es pesimista. El análisis amortizado calcula el costo promedio por operación sobre una secuencia de n operaciones, garantizado — no probabilístico.
costo amortizado por op = T(n) / n
donde T(n) = costo total real de n operaciones

si T(n) = O(n) → cada op cuesta O(1) amortizado

Los 3 métodos

Agregado

Calcular el costo total T(n) exacto para n operaciones y dividir entre n. Sencillo cuando hay una fórmula cerrada.

Contador (crédito)

Asignar crédito ĉ_i a cada op. Las baratas guardan crédito; las caras lo gastan. El saldo nunca puede ser negativo.

Potencial

Definir función Φ sobre el estado de la estructura. El crédito es el cambio en Φ. Más general y formal que el contador.

Método del Potencial — Fórmula

ĉ_i = c_i + ΔΦ
= c_i + Φ(D_i) − Φ(D_{i−1})

Sumando sobre n operaciones:
Σ ĉ_i = Σ c_i + Φ(D_n) − Φ(D_0)

Como Φ(D_0) = 0 y Φ(D_i) ≥ 0 siempre:
Σ c_i ≤ Σ ĉ_i ← el amortizado es cota superior del real
1
Φ(D_0) = 0 — la estructura vacía tiene potencial cero
2
Φ(D_i) ≥ 0 siempre — el potencial nunca puede ser negativo
3
ĉ_i constante — eso es lo que queremos demostrar

Ejemplo 1 — Contador Binario (+1)

Potencial

Φ = número de bits en 1

Sumar 1 a un contador binario de b bits. Si el número termina en k unos, hay que voltear k+1 bits: los k unos se ponen a 0 y un cero se pone a 1.

c_i = k + 1 (voltear k unos → 0, y un cero → 1)
ΔΦ = 1 − k (ganamos 1 uno, perdemos k unos)

ĉ_i = (k+1) + (1−k) = 2

Ejemplo 2 — Array Dinámico (resize)

Potencial

Φ = 2n − cap

Insertar en un vector que dobla su capacidad cuando está lleno. Si hay n elementos y cap de capacidad:

Inserción barata (n < cap):
c_i = 1, ΔΦ = 2(n+1)−cap − (2n−cap) = +2
ĉ_i = 1 + 2 = 3

Inserción cara (n = cap, resize → cap×2):
c_i = n+1, Φ_antes = 2n−n = n, Φ_después = 2(n+1)−2n = 2
ΔΦ = 2 − n
ĉ_i = (n+1) + (2−n) = 3

Reglas para diseñar una buena Φ

1. Φ(D_0) = 0 y Φ ≥ 0 siempre ← obligatorio para que el bound sea válido
2. Φ sube poco en ops baratas ← acumula crédito
3. Φ cae mucho en ops caras ← libera crédito para pagar
4. c_i + ΔΦ = constante ← eso es lo que queremos demostrar

Regla práctica: si la op cara cuesta f(n), Φ debe acumular ~f(n)/ops_baratas por inserción.
Binario: f(k)=k, ops_baratas≈k → acumular 1/op. Array: f(n)=n, ops≈n/2 → acumular 2/op.
